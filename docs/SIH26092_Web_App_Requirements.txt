1. Functional Requirements (What the app
must do)
Module A — Smart Scheme Recommender
Multi-step intake form: project type, estimated cost, annual family income, education status, caste category proof
status
Rules engine that maps inputs → scheme (Micro Finance ≤ ₹ 1.4L / Term Loan ≤ ₹ 50L / Education Loan)
Confidence/eligibility score display with plain-language explanation ("Why this scheme?")
Multilingual support (minimum Hindi + English toggle)
Module B — Financial Calculator
EMI calculator using standard formula: EMI = P × r × (1+r)^n / ((1+r)^n − 1)
Scheme-specific interest rate lookup (6.5%–15%)
Moratorium period handling (3–12 months, EMI start delay)
Amortization schedule table + downloadable summary
Module C — Geo-Spatial Partner Locator
Map view (Leaflet/Google Maps) showing nearby SCAs/Banks/NBFC-MFIs
Distance-based sorting from user's location
Filter by partner type and scheme category served
Mock "eligibility score" per partner (clearly labeled as simulated for demo)
Module D — Auth & Profile (optional, for judging polish)
Simple login/signup (or guest mode to skip friction in demo)

3. Tech Stack Recommendation
Frontend
Framework: React.js (or Next.js if you want SSR + easy deployment)
Styling: Tailwind CSS (fast to build clean UI under time pressure)
Maps: Leaflet.js + OpenStreetMap (free, no API key hassles) — or Google Maps JS API if you have a key
i18n: react-i18next for multilingual toggle
Charts: Chart.js or Recharts for amortization schedule visualization
Backend
Runtime: Node.js + Express, or Python + FastAPI (FastAPI is great if you want to bolt on ML later)
Rules engine: Plain conditional logic or a lightweight decision-table library — no ML model required for MVP
API design: REST endpoints — /recommend, /calculate-emi, /nearby-partners
Database
PostgreSQL or MongoDB for:
Scheme master data (rules, interest rates, limits)
Channel partner directory (name, location, type, category served, mock eligibility score)
User applications (if you add save/history)
For hackathon speed: SQLite or a simple JSON/CSV file can substitute if time is short
Hosting/Deployment
Frontend: Vercel or Netlify (free, instant deploy from GitHub)

4. Data You Need to Prepare
Before/During the Hackathon
1. Scheme rules table — you'll need to research and hardcode actual scheme parameters (income caps, loan
limits, interest rate bands, moratorium periods) from MoSJE/NBCFDC public documentation.
2. Channel partner directory — curate a sample CSV of ~20–50 real or representative SCA/bank branches (name,
lat/long, type, scheme category) for your demo region — full national coverage isn't needed for a hackathon.
3. Translation strings — prepare a JSON dictionary of UI text in Hindi (and optionally a regional language relevant
to your team/judges).

historical disbursement data for continuous improvement.
